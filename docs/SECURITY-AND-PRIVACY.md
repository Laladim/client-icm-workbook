# Keep the public template and private client separate

The public repository contains reusable guides, code, blank templates and fictional examples only. Install each client into its own empty private folder outside this repository. The installer refuses an existing target, a target inside the public template or a target that overlaps another marked client workspace. New workspaces are local-only and are not initialized as public Git repositories.

Use approved secure invitations and credential storage outside the workbook. Never paste passwords, tokens, private keys, cookies, recovery codes or access-bearing URLs into answers, Git or examples. Source references must omit credential values and unrestricted private data. Do not copy client lists, call transcripts, customer names, pricing, CRM exports or restricted documents between clients or into the public template.

Record each source's sensitivity, permitted use, owner, checked-at evidence, freshness/decision rule and storage location. A client name or internal profile does not grant testimonial consent. Use exact approval for names, quotes, screenshots and case studies. Keep retention, sharing, model/tool use and deletion rules client-specific; ask a qualified owner about actual regulated requirements.

Before publishing template changes, run the public-source audit and inspect the exact staged file list. The scanner is a useful check, not proof that all private information has been detected. A shared support example must be fictional or separately approved and sanitized.
